# 智能分析框架不足与渐进优化方案

更新日期：2026-09-21

## 1. 当前状态

当前系统已具备五类分析入口、异步任务、研究数据库、基础量化计算、运行日志和取消接口，但仍属于“基础量化原型”。股票和 ETF 仅完成少量本地指标，行业、筛选和比较为简化实现；公告、ETF档案、指数成分、事件抽取和 DeepSeek 尚未进入正式分析链路。

| 能力 | 状态 | 主要不足 |
|---|---|---|
| 单股/ETF任务与结果保存 | 已实现 | 状态仍主要依赖进程内存 |
| 本地行情与财务读取 | 已有骨架 | 历史时点、覆盖率和指标口径需完善 |
| 确定性评分 | 已有骨架 | 指标少，原实现存在回撤方向和缺失值问题 |
| 行业、筛选、比较 | 简化实现 | 无历史关系、规则确认和专用比较模型 |
| 外部公告与ETF数据 | 采集探针 | 尚未统一入库，分页与正文处理不完整 |
| 事件抽取与 DeepSeek | 未实现 | 缺客户端、结构化输出、校验与降级 |
| 证据链 | 已有骨架 | 证据粒度、唯一性和派生指标复算能力不足 |
| 历史回放与调度 | 未实现 | 缺可用日回放、监控和长期评测 |

## 2. 实施原则

- `market.db` 保持本地市场事实库定位，外部资料和分析结果只进入 `research.db`。
- 缺失数据不补零、不前向填充、不由模型猜测。
- 所有历史分析严格按公告日、发布时间和关系有效期取数。
- `quant_score` 由确定性代码生成，模型不得覆盖。
- 外部来源或模型失败时，仍返回本地量化报告。
- 任何展示数字必须能够追溯到原始记录或派生证据。
- 各阶段保持现有日报、推荐、排行榜和证券查询兼容。

## 3. 阶段0：建立可信基线

### 3.1 冻结运行基线

- 记录数据库表、最新日期、覆盖率和五类分析样例。
- 记录现有接口、页面、测试数量和外部数据空表情况。
- 页面标注“基础量化原型”。
- 验收：五类请求有可复现样例，后续版本可对比。

### 3.2 修复评分正确性

- 风险越高得分越低，最大回撤使用绝对损失幅度扣分。
- 股票和 ETF 使用不同风险阈值。
- 每个指标输出原值、标准化分、权重和贡献。
- 验收：回撤从 10% 增至 30% 时风险分下降，边界测试通过。

### 3.3 禁止缺失值补零

- 缺失指标不参与评分分母。
- 负 PE、无意义 PB 和异常财务值标记为无效。
- 单独计算覆盖率；关键字段缺失时降低置信度并限制评级。
- 验收：NULL 与真实 0 的结果不同，页面显示缺失原因。

### 3.4 修复历史时点

- 财务使用 `announce_date <= as_of` 的最新版本。
- 行情、公告、规模、净值和指数成分按可用日期截断。
- 当前行业关系不能回填至有效期以前。
- 验收：历史分析不能读到未来数据，回放可重复。

### 3.5 修复证据唯一性

- 证据使用全局唯一 ID，并保留运行内局部编号。
- 每条证据记录证券、日期、单位、口径、计算版本和来源主键。
- 派生指标保存输入范围与公式。
- 验收：连续分析不会覆盖旧证据，结果可复算。

## 4. 阶段1：确定性分析核心

### 4.1 统一事实包

每次分析生成证券身份、截止日、行情、估值、财务、资金、ETF产品、行业关系、事件、覆盖率、新鲜度和警告。事实包只能包含截止日已经可用的数据。

### 4.2 指标注册表

统一登记指标代码、名称、证券类型、来源、单位、公式、最小历史长度、异常值规则、缺失规则和版本，禁止不同模块重复计算同一指标。

### 4.3 股票评分

按顺序增加价值、质量、成长、趋势、风险和资金六个维度；每个维度至少两个有效指标才生成正式分数。总分保留每项权重和贡献。

### 4.4 ETF评分

依次增加收益趋势、风险、流动性、规模稳定性、净值折溢价、跟踪关系、跟踪误差、费率、同类排名和公司行动风险。缺指数行情时不计算跟踪误差，缺篮子时明确显示指数成分近似。

### 4.5 覆盖率和置信度

基于字段覆盖、新鲜度、官方事件、来源冲突、历史长度和关系验证确定高/中/低置信度，并输出所有降级原因。

## 5. 阶段2：官方外部数据

### 5.1 统一采集记录

所有采集器写入来源、范围、页数、记录数、重复数、错误、耗时、解析器版本和限速状态。

### 5.2 巨潮公告

完成机构映射、总页数分页、日期分段、公告ID幂等、目录与PDF解耦、重试、限速、文件哈希及发布时间控制。

### 5.3 公告正文

执行文本提取、质量检查、OCR降级、页码定位、页眉页脚清理、正文哈希；正文成功后才能进入事件抽取。

### 5.4 ETF与指数资料

接入深交所规模、上交所下载文件、申赎清单、基金档案、费率、季报持仓和公司行动；解析指数成分、权重、发布日期和有效期。无法获得历史版本时不得伪造。

### 5.5 版本化关系

建立股票—行业、股票—主题、股票—指数、ETF—指数、ETF—行业和ETF—主题关系，保存有效期、来源等级与验证状态。

## 6. 阶段3：事件与 DeepSeek

### 6.1 规则事件抽取

先按标题和公告类别识别财报、预告、分红、回购、减持、合同、重组、诉讼、处罚、问询、调研和ETF变更。

### 6.2 模型接入

- 密钥仅从 `DEEPSEEK_API_KEY` 读取。
- 模型配置、超时和重试进入本机配置。
- 网络和模型失败自动降级。
- 正文作为不可信数据隔离，防止提示注入。

### 6.3 结构化输出和校验

模型只输出事件类型、方向、期限、重要性、可信度、摘要、证据ID、风险和建议调整。校验器检查证据、数字、日期、实体和收益承诺，无法验证的内容删除或标记。

### 6.4 AI调整边界

单事件和累计调整均设上限；低可信度事件与单一辅助新闻不能调整总分。每项调整必须绑定证据ID。

## 7. 阶段4：五类完整研究能力

### 7.1 股票与ETF

分别建设专用结果模型和页面，显示分项评分、行业/同类位置、多空证据、事件时间线、数据状态和口径。

### 7.2 行业与主题

完成行业消歧、历史成分、行业指数、估值、盈利扩散、资金热度、代表股票和相关ETF。未验证主题关系不得生成正式主题结论。

### 7.3 自然语言筛选

先通过 `/api/screener/parse` 输出字段、运算符、阈值、单位、时间窗口和不支持条件，用户确认后再执行。不允许静默忽略条件或退化为全市场查询。

### 7.4 多标的比较

从主表确认证券类型，统一截止日、复权、币种和单位。股票与ETF分别展示适用字段，同指数ETF使用专用比较模板。

## 8. 阶段5：任务和前端

- 以 `analysis_run` 为状态唯一来源，服务重启后可以恢复。
- 日志由业务组件产生，记录实际数量、阶段、耗时和错误。
- 数据库、网络和模型阶段均检查取消；取消后不得保存正式结果。
- 五类分析采用专用前端组件，并统一展示覆盖率、新鲜度、来源状态、量化分、AI分、置信度和证据。

## 9. 阶段6：测试、回放和调度

- 测试评分方向、缺失值、历史时点、分页、哈希幂等、证据唯一性、模型引用、五类分析、取消、超时和旧页面回归。
- 使用历史公告日、财务可用日和历史成分进行回放，对比量化分与AI调整后的风险识别和后续表现。
- 建立每日公告/ETF规模任务、低频档案/指数任务、失败重试、数据新鲜度监控和来源失效告警。

## 10. 里程碑

| 里程碑 | 内容 | 通过条件 |
|---|---|---|
| A 结果可信 | 阶段0、1 | 无错误方向、无补零、无未来数据、证据不冲突 |
| B 官方事件闭环 | 阶段2、3 | 公告入库、正文、事件、模型及引用校验可降级运行 |
| C 五类能力完整 | 阶段4、5 | 五类专用流程和页面、持久化任务及真实日志完整 |
| D 长期运行 | 阶段6 | 自动更新、监控、回放和完整回归测试通过 |

实施必须按 A→B→C→D 顺序推进；未通过上一里程碑验收，不把下一阶段功能标记为正式可用。
