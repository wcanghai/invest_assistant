股票详细数据程序已经完成，第一批和第二批均已实现：

- 每日总股本和流通股本；

## 2. 数据库表

| 表名 | 主键 | 内容 |
|---|---|---|
| `stock_daily_bar` | 股票代码、交易日 | 不复权 OHLC、量、额、前复权因子 |
| `stock_capital_daily` | 股票代码、交易日 | 总股本、流通股本 |
| `stock_corporate_action` | 股票代码、事件日、类型 | 分红送配和复权事件 |
| `stock_trade_daily` | 股票代码、交易日 | 常用 GP 显式字段及全量 GP JSON |
| `stock_financial_report` | 股票代码、报告期、公告日 | 核心 FN 字段及 438 字段 JSON |

所有详细数据表均通过 `stock_code` 关联现有唯一证券主表 `stock_master`。

### 8.1 GP 历史空值复核和修复

针对 GP03、GP11、GP13、GP16、GP21 等字段在老股票上出现约 2,000 条记录的情况，采集程序
已经改为“自然年度窗口 + 字段批次”双重分段。每个自然年分别请求，避免长时间范围可能触发
接口返回上限。

修改后重新从上市日起回补四只股票，数据库记录数没有增加。进一步对中国平安进行了接口
直查：

| 请求范围 | GP03、GP16、GP21 返回情况 |
|---|---|
| 2007-03-01 至 2010-12-31 | `None` |
| 2011-01-01 至 2015-12-31 | `None` |
| 2016-01-01 至 2017-12-31 | `None` |
| 2018-01-01 至 2018-12-31 | 从 2018-06-05 开始返回 |
| 2026-01-01 至 2026-08-28 | 正常返回 |

因此，约 2,000 条不是采集被截断，而是从 `2018-06-05` 到 `2026-08-28` 恰好约有 2,000 个
交易日。早期显式列为空是通达信没有提供对应历史数据。

年度分段逻辑已经通过自动测试并作为定向修复选项保留。全市场任务默认使用完整日期范围，
因为实测不存在截断，可显著减少接口调用。不能对 2018 年以前的缺失记录补零或向后回填，
否则会把“数据源不存在”错误表示成真实数值。

## 9. 使用方式

初始化表：

```powershell
python -m stock_data.main init-db
```

全部证券池全量获取：

```powershell
python -m stock_data.main full-load --end-date 2026-08-28
```

每日增量：

```powershell
python -m stock_data.main daily-update --date 2026-08-28
```

单股指定数据域修复：

```powershell
python -m stock_data.main repair-stock `
    --stocks 600519.SH `
    --start-date 2001-08-27 `
    --end-date 2026-08-28 `
    --domains bar,capital,action,trade,financial
```

数据检查：

```powershell
python -m stock_data.main check-data `
    --stocks 601318.SH,000333.SZ,600519.SH,688981.SH
```
