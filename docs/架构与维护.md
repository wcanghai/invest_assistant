# 模块职责与维护边界

生产源码实际位于 `src/invest/`，统一入口不再向 Python 搜索路径插入旧项目根目录。
旧 `security_pool`、`stock_data`、`factor_strategy`、`etf_strategy`、`daily_report`
与 `tdx_client.py` 已移至 `backups/module_relocation_20260917/legacy_source/`。

| 目录 | 当前内容 |
|---|---|
| `core` | 应用配置、项目路径、跨进程锁、文件替换重试、研究运行档案 |
| `providers` | 通达信客户端、证券池/股票接口适配、网页报价采集 |
| `storage` | 证券池、股票、因子、ETF、日报的数据访问；SQL 资源；四库迁移与核对 |
| `market/security_pool` | 证券池更新、字段转换及 ETF 日行情维护 |
| `market/stock` | 股票更新、财务增量、交易日与证券范围查询 |
| `market/etf_collect.py` | 有明确代码和日期范围的 ETF 补采 |
| `research/stocks` | 股票因子、评分、组合、股票回测、MVP 策略 |
| `research/etf` | ETF 策略与回测、三因子轮动、十年/全市场研究、报告校验 |
| `accounts` | 账户快照、成交、账户事件导入、计划与对账 |
| `reporting` | 日报读取与生成、导出、本地 HTTP 服务及静态页面 |
| `jobs` | 每日行情任务、完整性检查、日报批次与历史补跑 |

股票和 ETF 保留各自的回测引擎，没有合并交易逻辑。业务函数不调用 PowerShell。
当前两个正式任务的 PowerShell 文件负责选择运行环境和启动 Python；触发时间、名称、
用户和权限保持原任务定义。非正式的手工全历史采集脚本仍有 PowerShell 编排，见核验记录。

## 数据与并发

`market.db` 保存行情、财务、证券分类及采集证据；`research.db` 保存策略与回测结果；
`accounts.db` 保存四类账户表；`reports.db` 保存网页观察记录与版本化日报。
每个迁移目标均有自己的 `schema_migration`。

股票研究通过只读附加市场库和可写研究库工作；ETF 数据集与日报采用只读市场连接。
不会为了读取行情而创建市场库。市场更新命令、每日更新和日报补跑共用
`market.update.lock`。锁由操作系统释放，不删除可能仍被使用的锁文件。
副本任务的默认状态保存到副本附近，避免污染正式状态。

## 配置和输出

默认配置为 `config.toml`，本机覆盖为不入库的 `config.local.toml`，策略配置位于
`configs/`。显式参数覆盖本机配置，本机配置覆盖默认配置；默认路径从项目根目录解析，
显式相对路径从调用目录解析。当前支持的是项目本地虚拟环境安装。

研究统一入口把新输出放入类型目录下的日期/独立运行编号目录，并保存
`run_manifest.json`，包括完整应用和策略配置、绝对参数、提交号、实际源码哈希、
输入表行数与截止日期、输出清单、完成或失败状态。ETF 自身的输入证据摘要继续保留。
股票因子与回测也导出完整评分、组合、净值或成交 CSV。旧报告保留原位置与内容。

## 验证入口

```powershell
.venv-report/Scripts/python.exe -m pytest -q --basetemp .tmp/validation
.venv-report/Scripts/python.exe -m compileall -q src tests
.venv-report/Scripts/python.exe -X utf8 scripts/check_python_style.py
.venv-report/Scripts/python.exe -m pip check
```

`scripts/verify_module_cutover.py` 接受显式旧源码备份与临时输出目录，比较迁移前后算法。
它只使用合成数据。`scripts/relocate_modules.py` 是此次迁移的机械转换记录，
不是日常运行入口；旧目录已归档后不要重新执行 `stage` 覆盖后续修复。
