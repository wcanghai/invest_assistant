# ETF 量化系统：使用与技术设计

本模块实现资产池筛选、五种目标权重策略、统一回测和人工成交对账。
源数据库为 `data/security_pool.db`，研究及账户账本为 `data/etf_strategy.db`。
既有股票策略和 `factor_strategy.etf_rotation` 入口保留。

## 1. 当前边界

- 实盘采用人工执行清单，不接券商，不自动下单。
- 不预设账户资金、个人风险偏好或持仓上限。未提供账户参数时只输出权重。
- `exploratory` 默认使用原始价格，是有生存者偏差的探索研究，不能当作正式绩效。
- `validated` 模式需要复权因子、分红拆合份完整性证明；仅补入因子不会自动通过。
- `validated_research` 还需要完整历史证券范围、时点身份、分类和交易日历的证明。
- `manual_execution_ready` 进一步要求实际账户对账一致、可卖数量、当日报价、
  交易单位/精度、下一交易日、费率、容量限制和账户仓位限制全部齐备。
- 日线 OHLC 回测不能验证真实盘口成交；一字价日保守不成交，其他成交仍为模型估计。

## 2. 安装与入口

使用安装了 numpy、pandas 的 Python。本机系统 Python 可运行，不使用只有日报依赖的
`.venv-report`。需要重新安装时执行 `python -m pip install -r requirements-etf.txt`。

```powershell
python -m etf_strategy --help
python -m etf_strategy migrate
python -m etf_strategy audit
python -m etf_strategy import-data --table etf_classification `
  --input configs/etf_classification_seed.json
python -m etf_strategy universe --date 2026-09-11
python -m etf_strategy universe --date 2026-09-11 --pool factor
python -m etf_strategy signal --date 2026-09-11 --strategy dual_momentum
python -m etf_strategy backtest --strategy trend --start 2020-01-01 --end 2026-09-11
python -m etf_strategy compare --start 2020-01-01 --end 2026-09-11
python -m etf_strategy trade-plan --date 2026-09-11
```

每次运行保存配置、完整 JSON 结果、适用的 CSV 和内容哈希运行编号。
CLI 仅打印结果位置，完整结果保存在 `reports/etf_strategy/<运行编号前16位>/`。
历史运行不覆盖；相同输入与配置产生同一运行编号。

策略 ID：`dual_momentum`、`trend`、`risk_parity`、`strategic`、`factor_rotation`。
使用 `--config configs/etf_research.json` 指定版本化参数，未知参数会报错。
严格模式使用 `--config configs/etf_validated.json`；证据不足返回 `blocked`，不伪造信号。
`--db` 选择源库，`--results-db` 选择研究库，`--output` 选择文件目录。

## 4. 数据补齐、验证和接口

源库采用附加表和可重复迁移；`etf_daily.forward_factor` 保存原先被丢弃的采集字段。
常规 ETF 入库继续保存该字段；扩展表存在时记录 bar/nav/size/adjustment 的采集时间。
未知发布时间保持 NULL，不拿采集时间冒充历史发布时间。

```powershell
$env:PYTHONPATH = 'D:\software\tdx\PYPlugins\user'
python -m etf_strategy collect --codes 510300.SH 511010.SH 518880.SH `
  --start 2005-01-01 --end 2026-09-11
python -m etf_strategy validate-prices --codes 510300.SH 511010.SH 518880.SH
```

`collect` 仅对显式代码和日期范围操作：补存因子、记录交易日历及原始公司行动返回；
对行情只补空值，不覆盖原有非空 OHLC。原始事件缺单位、登记日、支付日时不会臆造标准事件。
接口空表不表示“从未分红”。最新日历未给出下一交易日时，不生成有数量的人工交易单。

`validate-prices` 比较因子变点与经核验事件，输出无法解释的变点、事件对应理论比例和差异。
它是诊断工具，不自动证明全历史事件完整，也不自动签发验证记录。

标准化资料以 JSON 数组通过 `import-data --table <表名> --input <文件>` 导入，字段与
`etf_strategy/schema.sql` 一致，逐批原子校验：

|表|用途与必要信息|
|---|---|
|etf_classification|代码、生效起止、当时已知时间、类别、市场、暴露组、纯风格、来源、核验标记|
|etf_adjustment|代码、交易日、正数因子、来源、采集时间|
|etf_action|事件ID、代码、登记/除息/支付日、每份现金、份额乘数、已知时间、来源|
|etf_validation|代码、覆盖区间、独立核验来源、乘法方向、事件完整性等确认|
|etf_identity|上市/终止日、当时已知时间、来源；可新增历史终止产品基础记录|
|etf_calendar|交易日、来源、是否核验|
|etf_rule|交易单位、价格步长、T+0标记及生效时间和来源|
|etf_universe_validation|区间内终止产品和历史映射完整性证据；不存在时不得提升研究等级|

复权序列只计算信号；成交和持仓估值使用原价。分红事件按原始每份权益记账，不能同时
用复权估值再加现金。调整因子并不天然等于严格的分红再投资指数，核验必须检查供应商约定。

## 5. 五种策略实现

共用 `Dataset.universe()` 与 `target()`；策略不操作现金账户。
`target()` 返回信号日、状态、权重、现金权重、因子值、诊断、完整池及质量等级。

1. **双动量**：126/252日收益均值；MA200上方且动量正；最多Top3；60日逆波动权重；
   n只合格时资金暴露为n/3。波动率目标及权重上限仅在显式配置时启用，释放资金留现金。
2. **趋势**：四类各25%，类内暴露组等权；独立MA200过滤，不通过的原份额留现金。
3. **风险平价**：126日窗口，至少100个共同观测；10%向对角收缩；先类内等风险贡献、
   再类别间等风险贡献。坐标下降求解，残差低于1e-8，最多10,000轮；失败取消新目标。
   风险预算计算后再MA200过滤，不归一化剩余持仓。
4. **战略配置**：四类各25%，类内等权，季度末恢复目标；月末仍检查现有持仓质量，
   异常输出告警，不模拟无法成交的强制卖出。
5. **纯风格轮动**：同一市场价值/质量/低波均合格才准入；每种风格保留一个代表；
   同样动量及趋势规则，最多两个风格各50%。缺一类则 `not_eligible`。

月末通过真实后续交易日跨月判断，不能把任意回测截止日当月末。`signal` 可输出最新
观察权重，但有数量的人工清单只能来自计划调仓日。

## 6. 回测账户、统计与比较

每日顺序：除息/拆合份及到期现金 → 前日目标成交 → 收盘原价估值 → 登记日持仓留档
→ 收盘信号。除息日确认应收、支付日转现金；卖出不会抹去已登记的分红权利。
停牌或缺失时保持原持仓，记录陈旧估值；当日未完成订单到期，不悄悄延续旧目标。

权重层初始净值1、分数份额、单边3bp费用＋5bp滑点、现金零收益，不模拟最低佣金或整手。
账户层传 `--account <JSON>`，必须提供以下字段：

```json
{
  "initial_cash": 100000,
  "fee_bps": 3,
  "minimum_fee": 5,
  "slippage_bps": 5,
  "lot_sizes": {"510300.SH": 100},
  "max_adv_participation": 0.01
}
```

以上数字仅演示文件结构，不是默认账户配置；所有可能交易代码必须提供交易单位。
容量仅基于历史ADV估计，不代表真实盘口可成交量。实际交易以券商回报为准。

`compare` 输出五策略、成本翻倍、有效期、共同起点重新持有现金运行结果、60/40开发验证
区间及声明。无有效持仓策略从共同活跃区间比较中排除，仍完整保留失败原因。
统计包括CAGR、最大回撤、零无风险Sharpe、Calmar、最长/进行中回撤交易日数、年度收益、
单边换手（买卖成交额合计/2）、平均现金比例。CAGR按自然时间，波动/Sharpe按252交易日。
未修复回撤不标记为已回本。历史验证集不冒充真正前瞻未见数据。

## 7. 人工成交与对账

```powershell
python -m etf_strategy import-account --input account_snapshot.json
python -m etf_strategy import-fills --account-id my_account --input fills.json
python -m etf_strategy import-account-events --account-id my_account --input cash_events.json
python -m etf_strategy reconcile --input broker_snapshot.json
python -m etf_strategy trade-plan --date 2026-09-30 --strategy trend `
  --account broker_snapshot.json --execution execution_settings.json
```

账户快照结构为 `account_id, as_of, cash, holdings`；交易清单另要求 `sellable`。
`holdings`、`sellable` 是代码到实际份额的映射。首次快照创建账户；以后通过成交和账户事件
更新，不能重新导入不同快照覆盖已有账本。`reconcile` 比较现金与每只持仓，差异不为零时
CLI拒绝生成下一份数量清单。

成交数组的每项字段：`fill_id, timestamp, code, side, quantity, price, fee`。
价格和费用来自真实券商回报；同账户相同成交ID同内容跳过、不同内容报错；整批事务提交，
资金不足或负持仓整批回滚。时间必须使用一致的本地ISO格式并按真实先后导入。

账户事件字段：`event_id, timestamp, kind, code, cash_amount, share_multiplier, source`。
支持 `dividend_paid`、`cash_transfer`、`split`，有来源且ID去重；不把分红现金伪装成买卖。

执行参数：`execution_date, fee_bps, minimum_fee, max_adv_participation, quotes,
max_asset_weight, class_caps`。quotes逐代码提供当日 `date, price, tradable`。
可卖份额不能超过券商返回；买入计划依赖卖出实际成交后刷新现金，不能按预计卖款盲目买入。
输出CSV包含方向、数量、限价、估计费用，附下一交易日15:00失效时间。
当前缺口未解决时仅输出观察权重，不会因为提供资金就绕过数据质量检查。

而不是把探索结果改一个标签就视为正式绩效。
