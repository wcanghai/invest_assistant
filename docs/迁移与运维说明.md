# 重构迁移与运维说明

## 迁移前检查

1. 确认两个 `Invest-*` Windows 定时任务处于空闲状态。
2. 使用项目 Python 执行 `python -m invest db check`。
3. 运行 `python -m invest db migrate`。该命令会通过 SQLite 备份 API 在
   `backups/pre_migration_时间戳/` 创建旧库副本，并拒绝覆盖任何已存在的新库。
4. 运行 `python -m invest db verify`。它比较逐表行数和数据摘要，并执行完整性检查。

## 命令迁移

| 旧入口 | 新入口 |
|---|---|
| `python -m security_pool.main` | `python -m invest market pool` |
| `python -m stock_data.main` | `python -m invest market stock` |
| `python -m security_pool.etf_data` | `python -m invest market etf` |
| `python -m factor_strategy.main` | `python -m invest research factor` |
| `python -m factor_strategy.mvp` | `python -m invest research mvp` |
| `python -m factor_strategy.etf_rotation` | `python -m invest research three-momentum` |
| `python -m etf_strategy` | `python -m invest research etf` |
| `python -m daily_report.cli` | `python -m invest report run` |

策略命令仍接受原有参数、策略名称和输入 JSON 格式。使用 `--db` 或结果库参数时，
显式指定值优先于配置默认值。

## 定时任务切换与回滚

运行 `scripts/deploy_tasks.ps1` 前必须已通过迁移核对。该脚本先导出现有任务定义，
暂停任务，再重新注册同名任务。若迁移或验证失败，不要执行部署脚本。

回滚时使用 `scripts/rollback_tasks.ps1` 恢复导出的任务 XML，并将
`backups/pre_migration_时间戳/` 中的数据库副本恢复到旧位置。恢复前应先停止项目
写入进程；如切换后已有新增数据，先完整保存新数据库副本。
