## 1. 设计结论

建议以本项目 `data/security_pool.db` 为境内行情和证券信息的主要来源，新增独立
`daily_report` 模块：同步结束 → 数据就绪检查 → 一致性读取 → 指标计算 → 保存快照 →
Markdown/本地网页展示。报告结果存入独立 `data/daily_report.db`，避免重复存储全量历史行情。

第一版建议覆盖 A 股、ETF、行业概览、自选证券和申购日历；指数行情需要补充采集。
旧版的期货、美股、虚拟货币及发行信息补全作为可配置扩展，具体范围待用户确认。

## 4. 建议日报内容

1. 报告头：报告交易日、生成时间（Asia/Shanghai）、版本、完整/部分状态、核心覆盖率。
2. 市场概览：沪深北股票成交额、上涨/下跌/平盘数量、缺失数量，与上一交易日比较。
3. 主要指数：如启用，补采独立指数日线；不能把成份股收益平均值当作官方指数涨跌幅。
4. 自选股票：收盘、涨跌幅、成交额、三年价格分位、PE/PB、行业、数据日期。
5. ETF：沿用旧名单或用户指定名单；收盘、涨跌幅、成交额、历史价格位置。
6. 行业概览：按当日行业快照计算等权平均涨跌幅、上涨占比和成交额，注明这是样本统计。
7. 新股新债：本地申购事件；上市日、中签率、评级等缺失内容按扩展配置补采。
8. 数据质量附录：来源、字段单位、实际覆盖、异常证券及过期栏目。

策略结果可作为独立可选章节，必须有当日成功运行结果和配置版本，不自动生成交易指令。
不默认引入 AI 摘要或新闻解读；规则模板即可生成可验证的概览文字。

## 5. 指标口径

- 市场样本：目标日 `stock_snapshot` 中活动 A 股；市场宽度包含 ST，明确排除未上市证券。
  停牌单列，不计为平盘；缺失行情单列。自选和策略筛选条件单独配置。
- 涨跌幅：优先使用日线 `pct_change`；缺失时仅在 `pre_close > 0` 且口径可信时计算。
  不能直接用上一条原始收盘替代除权参考价。缺失则显示“—”。
- 成交额：`amount_10k` 是万元，除以 10,000 转为亿元；按股票汇总，避免股票与指数重复计算。
  覆盖不完整时标为“已覆盖股票成交额”，不称全市场官方成交额，更不能称净流入。
- 三年价格分位：在 `[D减三年, D]` 内，有效历史价格不高于 D 日价格的比例。
  沿用旧版最低 500 个有效样本、首个样本距窗口起点不超过 45 天，并检查窗口缺口。
  20%/80% 可沿用作价格位置标签，不能称估值高低。
- 股票跨期价格：参考本项目 `factor_strategy/data.py` 的 `close * forward_factor`，
  开发时用除权样例核验因子语义；缺因子不默认补 1。展示收盘价仍用原价。
- ETF：当前缺统一复权序列，若展示原始价格分位，显著标注未复权；检测到分红或拆合份
  未能校正时不输出可比性结论。不得将原价收益表述为含分红总回报。
- 财务和估值：估值取 D 日证券快照，财务只取 `announce_date <= D` 的可用记录。
  缺少历史快照则栏目缺失，不回用最新 `stock_current`。财报非每日发布，不要求报告期等于 D。
- 多市场：每行分别记录市场交易日、时区及获取时间；境外节假日可正常展示最近完成的交易日。
  虚拟货币的实时 24 小时变化与日 K 线分开存储，不能把实时价写作完整日收盘。

## 6. 数据流与生成条件

现有 `scripts/run_daily_market_sync.ps1` 已串联股票与 ETF 更新，并调用
`scripts/check_daily_sync_status.py`。接入点放在同步检查之后；同时处理“数据已经完整，
但日报不存在”的提前退出分支，避免报告漏生成。

新增就绪检查分两层：

1. 采集层：目标日期、证券池快照、各必需数据域同步状态、任务失败情况。
2. 内容层：目标日应有行情的证券实际覆盖、价格有效性、涨跌幅可计算性、自选标的数据时效。

建议严格模式：应有行情证券全部覆盖且必需字段通过校验才标记完整；原因已确认的停牌、
未上市证券从应有行情集合中扣除。无法解释的缺失不能被 `SUCCESS` 掩盖。
到截止时间仍有缺失，可以生成醒目标注的部分报告；核心数据完全不可用时不生成正式报告。
具体截止时间、是否允许部分报告，待用户确认。

读取主库使用 `mode=ro` 和一个短只读事务，完成就绪校验及所需数据提取后立即结束事务；
计算、外部请求和渲染在事务之外执行，避免长时间阻碍 WAL 回收。
主库及报告库无法形成共同事务，以保存到报告中的输入快照、来源时间和校验摘要追溯。

非交易日默认展示最近交易日报并注明日期，不复制成一份新 A 股日报。
若用户选择早报/全市场自然日日报，再增加独立报告类型及日历规则。
历史补报仅读取截至 D 的历史数据；缺乏当时公告或实时快照时显示不可重建。

## 7. 模块、存储及接口

建议目录：

```text
daily_report/
  config.py             # 配置与自选名单
  models.py             # 快照、栏目状态、质量结果
  repositories.py       # 主库只读查询、报告库持久化
  readiness.py          # 交易日与实际数据检查
  metrics.py            # 纯数据指标计算
  service.py            # 生成编排及版本管理
  rendering.py          # Markdown/HTML 共用结构化快照
  cli.py                # generate/check/list/export
  sources/              # 可选外部来源适配器
  web/                  # 本地只读浏览和历史版本
configs/daily_report.json
```

独立报告库建议包含：

- `report_runs`：运行 ID、目标日期、开始/结束时间、状态、异常和质量摘要。
- `daily_reports`：报告类型、日期、版本、生成时间、配置哈希、数据指纹、模板/计算版本、
  状态、结构化 JSON、Markdown；唯一约束为报告类型 + 日期 + 版本。
- `report_sources`：关联报告版本，记录来源、实际数据日期、获取时间、覆盖率和原因。
- 外部扩展启用后再增加 `external_bars`、`offering_events` 等表，并保留数据源与单位。

相同输入指纹重复生成返回已有版本；数据补齐或修订生成新版本，保留旧版。
部分报告不能覆盖完整报告；网页分别标明最新完整版本和正在补齐的目标日期。
数据库唯一约束与事务处理跨进程竞争，进程内锁仅作为优化。
数据库快照为导出依据，Markdown 文件可重新生成，防止文件写失败导致报告内容丢失。

拟议命令（尚未实现）：

```powershell
python -m daily_report.cli check --date 2026-09-11
python -m daily_report.cli generate --date 2026-09-11
python -m daily_report.cli export --date 2026-09-11 --format markdown
python -m daily_report.web --host 127.0.0.1 --port 8000
```

网页建议提供最新报告、历史日期、版本切换、Markdown 下载和数据质量详情。
网页浏览不隐式发起全市场采集；定时任务或 CLI 负责生成。

## 8. 实施顺序与验收

1. 确认市场范围、自选名单、报告时间、交付形式与缺失处理规则。
2. 实现本地数据适配、就绪检查、纯指标计算、JSON/Markdown 快照及幂等持久化。
3. 对 9 月 11 日生成样例，核对缺失证券、金额单位、除权日和历史分位边界。
4. 接入同步完成后的生成步骤，实现重试和补齐新版本，再建设本地网页。
5. 按确认范围加入指数、海外行情和发行信息补全；每个来源先验证可用性及单位。

必要验收：同输入重复运行不重复入库；并发生成唯一；部分变完整保留历史；
同步成功但行情缺失能被识别；历史补报不读未来数据；非交易日不误标日期；
停牌/新上市/除权/空值处理正确；外部栏目失败不阻断独立境内栏目；
Markdown 与网页数值一致；源码库只读，不重复复制全量行情。

性能先在当前数据库实测；仅对自选证券查询三年窗口，市场统计只扫目标日及必要比较日，
避免每次日报重跑全历史因子或回测。不预设未经测量的耗时承诺。
